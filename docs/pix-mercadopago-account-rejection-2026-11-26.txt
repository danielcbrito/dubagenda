The receiver is resolved before creating a pending_booking:
- Account approved + provider mercadopago + seller token -> Mercado Pago.
- Account approved + provider woovi + own AppID -> Woovi.
- Missing, pending, rejected, mismatched or disconnected account -> controlled
  account-unavailable response (409), without creating a hold.
There is no fallback to the master account or to a different payment provider.

Mercado Pago charges use the seller token, external_reference=book-<hold ID>,
an idempotency key and the existing mercadopago-oauth callback. Its QR is returned
as wooviPayment to preserve compatibility with the unified checkout. Both paths
write woovi_charges, and a failed local save after bank creation is reported as
requiring reconciliation rather than claiming a successful local confirmation.

more than one day. No new secret is required for this valid connection. Existing
OAuth secrets, when available in the runtime, permit token refresh near expiry;
otherwise a still-valid token is used until expiry. An expired connection needs
reconnection in the barber app, never a fallback to the platform account.
OAuth onboarding and webhook management remain owned by the barber application.
